# Configurator — context voor Claude

Productconfigurator (configureren → prijzen → offerte) voor maatwerkmeubelen, eerste case: zitmeubelen voor een Belgische maker (vermoedelijke pilootklant Corneille & Silence, Harelbeke). Aparte app, koppelbaar met het ERP **Missing Link** (REST API met etag/If-Match en idempotency keys). Taal: **TypeScript**. De gebruiker (Jonas) is functioneel analist/implementator, geen programmeur: antwoord in het Nederlands, in gewone taal.

**Lees eerst `docs/overdracht.md`** voor de stand van zaken, links en open punten. Voor alles rond 3D, boven- en vooraanzicht: gebruik de skill `zetel-3d` (`.claude/skills/zetel-3d/SKILL.md`). **Een model maken of verbeteren: volg `docs/werkwijze-3d.md`** (zes vaste stappen: bron, opbouw en bouwstijl, maten, afwijkingen, controleblad, vastleggen).

## Structuur
- `packages/core`: de motor (geen UI/ERP-afhankelijkheid). Formules als Excel-tekst → JsonLogic (`formule.ts`, `logica.ts`), productmodel (`types.ts`, `motor.ts`), modelcontrole, SVG-tekening (`svg.ts`), materialen, vrij ontwerp (`ontwerp.ts`: elementen, opties, vormgeving), vooraanzicht, 3D-opbouw (`ruimtelijk.ts`), zachte vormen voor de 3D (`zachtevorm.ts`, uitleg `docs/zachte-vormen.md`), doorlopende opbouw van een rij zitelementen als één zetel, ook in een boog (`doorlopend.ts`, Doha en Montego).
- `packages/core/voorbeelden`: demomodellen (kast, sofa per cm, zetelcatalogus `vrij-ontwerp.ts`, modellen `modellen.ts`). **Alle prijzen zijn verzonnen.** Proef met een echt 3D-bestand (4/11): `core/src/echt3d.ts`, `voorbeelden/proefmodellen.ts`, bestanden in `demo-web/modellen3d/` (geen model van de klant, niet in de huisstijlversie); uitleg `docs/echte-3d-modellen.md`.
- `packages/demo-web`: klikbare demo, gebundeld met esbuild tot één HTML-bestand (`npm run build -w @configurator/demo-web` → `dist/configurator-demo.html`). three.js 0.187 (met de uitbreidingen voor nabewerking en `three-gpu-pathtracer` voor de fotomodus) zit mee in de bundel; er wordt niets van een CDN geladen.
- `packages/bouw-web`: aparte demo voor de bouwsector (ramen, deuren, aanbouw) op dezelfde motor, model in `core/voorbeelden/aanbouw.ts` + `aanbouw3d.ts` (`npm run build -w @configurator/bouw-web` → `dist/bouw-configurator.html` en `-offline.html`). Sinds 1/11 ook plattegrond (ruimtes, muren, openingen, meubels: `core/src/plattegrond.ts`, `plattegrondsvg.ts`), raam/deur-model (`voorbeelden/raam.ts`, `raam3d.ts`), offerte met posities (`core/src/offerte.ts`), catalogus inrichting en gevelmaterialen (`voorbeelden/inrichting.ts`) en voorbeeldwoning (`voorbeelden/woning.ts`). Ronde 5: gevel-editor (`bouw-web/src/gevel-ui.ts`, materialen per muurvlak en sokkel), enkel ramen zonder woning (`bouw-web/src/ramenlijst-ui.ts`, `voorbeelden/maatlijst.ts`), klantweergave; analyse gebruiksgemak: `docs/analyse-gebruiksgemak.md`. Onderzoek: `docs/onderzoek-bouw-ramen-deuren.md`, analyse: `docs/analyse-bouw-woning-demo.md`, begrippen: `docs/begrippen-bouw.md`, concurrentie (LogiKal, ReynaPro, Chacal): `docs/onderzoek-raamsoftware.md`. Voor alles rond de bouwdemo (plattegrond, verdiepingen, gevels, werf, raam-3D): gebruik de skill `bouw-woning` (`.claude/skills/bouw-woning/SKILL.md`).
- `scripts/3d`: vast gereedschap voor de 3D (sinds 11/11), schrijft naar `werkbank/` (niet in git): `npm run controleblad` (elk model naast zijn foto, met oordeel en opmerking per model), `npm run modelbeelden` (beelden van modellen of een reeks keuzes, decors, lichtsferen), `npm run lichtmeting` (bovenkant en voorkant tegenover de staal, per lichtsfeer), `python3 -I scripts/3d/modelfotos.py` (grote foto's en maten van productpagina's naar `fotos-bron/`). Gedeelde basis: `scripts/3d/werkbank.mjs`. Bouwstijlen (het karakter van een zetel in één keuze): `packages/core/voorbeelden/bouwstijlen.ts`.
- `docs/`: analyse en stappenplan, fase 0-sjabloon, onderzoek, overdracht, afbeeldingen, en de 3D-kennisbank `docs/3d-technieken.md` (welke 3D-techniek waarvoor, lessen, werkwijze, advies ramen en deuren). Obsidian-export: `python3 -I scripts/obsidian_export.py` (nieuwe documenten toevoegen aan `NOTITIES`).

## Werkwijze
- Controles vóór elke commit: `npm test` (vitest) en `npm run typecheck` in de root. Bij een wijziging aan de 3D (of wat erin komt) ook `npm run beelden` (beeldvergelijking, ±2 min, `beeldtest/LEESMIJ.md`); een bewuste wijziging vastleggen met `npm run beelden -- --vernieuw` en de nieuwe referentiebeelden mee committen.
- Na een ronde aan de modellen: `npm run controleblad` en de pagina (privé) aan Jonas geven; na een wijziging aan het licht: `npm run lichtmeting`. Maak geen losse wegwerpscripts om beelden te vergelijken: breid `scripts/3d` uit.
- Eerst de gegevens van een model aanpassen (bouwstijl, maten, afwijkingen); de motor alleen voor een regel die voor meer modellen geldt, met een test.
- Code, namen en commentaar in het Nederlands, zoals de bestaande code.
- Branch: `claude/vigilant-cray-yi2j33` (enige branch in de repo, dus geen PR mogelijk).
- 3D lokaal testen: Chromium met `--use-angle=swiftshader --enable-unsafe-swiftshader` (zonder grafische kaart; kwaliteit *Mooi* is daar ±7 s per beeld, gebruik *Snel* of wacht lang). De 3D draait sinds 4/11 op `WebGPURenderer` (WebGPU, anders WebGL2): in de cloud is er geen WebGPU, dus daar test je de WebGL2-terugval; WebGPU zelf alleen op een echt toestel (de M5 in de toonzaal). Beelden nemen met `canvas.toDataURL()` (in de WebGL2-terugval met bewaard beeld) i.p.v. een elementscreenshot; in de app via `viewer.beeld()` of `foto()`. `window.__zetel3d` geeft in de ontwerper de 3D-weergave (bv. `fotoRealistisch({ stappen: 6, breedte: 520 })` voor een snelle proef van de fotomodus, ±2 min in swiftshader).
- Modellen van de klant niet verzinnen: wat uit foto's is afgeleid, markeren als benadering.
- De versie in de huisstijl van de klant (`configurator-corneille-silence.html`) alleen als bestand geven, niet publiek publiceren.
